SLIDE 11 - METHODOLOGY: FEATURE EXTRACTION
================================================================================

What is Feature Extraction?
Converting raw URLs into numerical features that ML algorithms can process

57 Features Extracted Per URL:

LEXICAL FEATURES (URL Content):
1. URL Length - Total characters in URL
2. Domain Length - Characters in domain name
3. Subdomain Length - Characters in subdomain
4. Path Length - Characters in path
5. Parameter Count - Number of query parameters
6. Special Characters - !, @, #, $, %, etc.
7. Digit Ratio - Percentage of digits in URL
8. Uppercase Ratio - Percentage of uppercase letters
9. Lowercase Ratio - Percentage of lowercase letters

STRUCTURAL FEATURES (URL Organization):
10. Number of Dots - Separators in domain
11. Number of Slashes - Path separators
12. Number of Hyphens - Hyphens in domain
13. Subdomain Count - How many subdomains
14. TLD Type - Top-level domain (.com, .org, etc.)
15. Has HTTPS - Boolean (1 if https, 0 if http)
16. Has IP Address - Boolean (uses IP instead of domain)

ENTROPY FEATURES (Randomness/Pattern Complexity):
17. Domain Entropy - Randomness in domain name
18. Subdomain Entropy - Randomness in subdomain
19. URL Entropy - Overall URL randomness
20. Hostname Entropy - Randomness in hostname

KEYWORD FEATURES (Content Analysis):
21. Has Suspicious Keywords - Presence of common phishing keywords
22. Suspicious Keyword Count - How many suspicious keywords
23. Has Brand Keywords - Presence of known brand names
24. Brand Keyword Count - How many brand keywords

ADVANCED FEATURES:
25-57. Additional computed features based on combinations and patterns

Why 57 Features?
- Captures multiple aspects of URL structure
- Different algorithms benefit from different features
- Rich feature set improves model accuracy
- Redundancy helps with robustness

Feature Extraction Process Per URL:
1. Parse the URL into components
2. Calculate each feature value
3. Create feature vector [f1, f2, f3, ..., f57]
4. Output: Feature-enriched dataset

SLIDE 12 - METHODOLOGY: DATASET CLEANING
================================================================================

Why Dataset Cleaning is Important:
- Raw data often contains errors and inconsistencies
- Duplicates can bias model learning
- Data leakage can give false sense of accuracy
- Poor quality data → Poor quality models

Steps in Dataset Cleaning:

1. DUPLICATE REMOVAL
   Problem: Same URL appears multiple times
   Impact: Model sees same example repeatedly, biases learning
   Solution: Keep only one copy of each URL
   Result: 27,679 → 27,672 URLs (removed 7 duplicates)

2. FEATURE LEAKAGE DETECTION
   Problem: Some features perfectly predict the target
   Example: is_https feature (all phishing had HTTP only)
   Impact: Model learns shortcut, fails on real-world data
   Solution: Identify and remove features causing leakage
   Removed Features:
   - is_https (100% correlation with label)
   - is_http (perfect separator)
   - has_query_params (data leakage)
   - no_protocol (data leakage)
   Result: 61 features → 55 features (removed 4 biased features)

3. LABEL INVERSION
   Problem: Original dataset had inverted labels
   - 0 meant legitimate (confusing)
   - 1 meant phishing
   Solution: Standardize to intuitive format
   - 0 = legitimate
   - 1 = phishing

4. CLASS IMBALANCE HANDLING
   Problem: Different number of phishing vs legitimate URLs
   Impact: Model biased toward majority class
   Solution: Data augmentation and HTTPS balancing
   Process:
   - Created duplicate URLs with both HTTP and HTTPS versions
   - Ensured 50/50 HTTPS distribution in both classes
   Result: 27,679 → 55,296 URLs (balanced dataset)

5. MISSING VALUE HANDLING
   Problem: Some URLs might have missing features
   Solution: Imputation or removal
   Strategy: Most features don't have missing values
   Fallback: Use default values (0 or mean)

6. CONSISTENCY CHECK
   Problem: Inconsistent URL formatting
   Solution: Normalize all URLs to standard format
   Process: Standard URL parsing and cleaning

Final Cleaned Dataset:
- 55,296 clean, balanced URLs
- 55 high-quality features
- No data leakage
- Ready for model training

Importance of Cleaning:
- Directly impacts model accuracy
- Prevents overfitting
- Ensures fair evaluation
- Results in generalizable models

Explanation:
Dataset cleaning ensures we're working with high-quality data. By removing
duplicates, fixing labels, and removing problematic features, we ensure the
model learns true patterns rather than shortcuts or artifacts in the data.

SLIDE 14 - METHODOLOGY: CROSS VALIDATION
================================================================================

What is Cross Validation?
A technique to evaluate model performance more reliably by testing on multiple
data splits

Why Cross Validation is Important:
- Single train-test split might be lucky or unlucky
- Different splits give different results
- Cross validation averages across multiple splits
- Provides more robust performance estimate
- Detects overfitting early

5-Fold Cross Validation Process:

Step 1: Divide Data into 5 Folds
Original dataset → Split into 5 equal parts
Each fold contains balanced mix of phishing/legitimate URLs

Step 2: Iterative Testing
Iteration 1:
- Train on: Fold 2, 3, 4, 5
- Test on: Fold 1
- Record metrics

Iteration 2:
- Train on: Fold 1, 3, 4, 5
- Test on: Fold 2
- Record metrics

Iteration 3:
- Train on: Fold 1, 2, 4, 5
- Test on: Fold 3
- Record metrics

Iteration 4:
- Train on: Fold 1, 2, 3, 5
- Test on: Fold 4
- Record metrics

Iteration 5:
- Train on: Fold 1, 2, 3, 4
- Test on: Fold 5
- Record metrics

Step 3: Average Results
Average Accuracy across all folds: 90.58%
Average Precision across all folds: 96.65%
Average Recall across all folds: 79.99%
Average F1-Score across all folds: 87.53%

Metrics Evaluated in Each Fold:

1. ACCURACY
   - Percentage of correct predictions
   - Formula: (TP + TN) / (TP + TN + FP + FN)
   - Our result: 90.58%

2. PRECISION
   - Of predicted phishing, how many were actually phishing
   - Formula: TP / (TP + FP)
   - Our result: 96.65%
   - Meaning: Only 3.35% false positives

3. RECALL
   - Of actual phishing URLs, how many we caught
   - Formula: TP / (TP + FN)
   - Our result: 79.99%
   - Meaning: We catch ~80% of phishing attempts

4. F1-SCORE
   - Balanced measure of precision and recall
   - Formula: 2 * (Precision * Recall) / (Precision + Recall)
   - Our result: 87.53%
   - Higher is better

Data Leakage Detection:
- Cross validation helps detect data leakage
- If model performs impossibly well, data leakage likely
- Our model performs realistically
- No signs of problematic leakage

Cross-Validation Accuracy Achieved:
> 98% in best scenarios
90.58% in realistic scenarios (our result)

Benefits of Our Cross Validation:
✓ More reliable performance estimate
✓ Detects overfitting
✓ Uses all data for both training and testing
✓ Robust across different data splits
✓ High confidence in model generalization

Explanation:
Cross validation is like stress-testing the model on different scenarios. Rather
than trusting a single train-test split, we test on 5 different splits and average
the results. This gives us confidence the model will work on real-world data.

SLIDE 17 - RESULTS: ROC CURVE

What is ROC Curve?
ROC = Receiver Operating Characteristic
A graph showing the performance of a classification model at different thresholds

ROC Curve Components:

X-Axis: False Positive Rate (FPR)
- Percentage of legitimate URLs incorrectly flagged as phishing
- Range: 0% to 100%
- Lower is better

Y-Axis: True Positive Rate (TPR)
- Percentage of phishing URLs correctly caught
- Range: 0% to 100%
- Higher is better

Ideal ROC Curve:
- Starts at bottom-left (0, 0)
- Goes straight up to top-left (0, 100)
- Then goes right to top-right (100, 100)
- This would mean: Perfect detection with no false alarms

Our ROC Curve:
- Curves from bottom-left toward top-left
- Demonstrates strong classification capability
- Significantly better than random (diagonal line)

Area Under Curve (AUC):
- Measures overall model quality
- Range: 0.5 (random) to 1.0 (perfect)
- Our AUC: 0.933 (excellent)
- Interpretation: 93.3% chance model ranks random phishing > random legitimate

AUC Interpretation:
0.5 = Random guessing
0.7 = Acceptable
0.8 = Good
0.9 = Excellent
0.95+ = Outstanding
Our 0.933 = Excellent performance

What ROC Tells Us:

1. STRONG CLASSIFICATION CAPABILITY
   - Model clearly separates phishing from legitimate
   - Not just slightly better than random

2. GOOD THRESHOLD FLEXIBILITY
   - Can adjust threshold based on needs
   - Trade-off between false positives and false negatives
   - Different security requirements supported

3. ROBUST ACROSS OPERATING POINTS
   - Works well at different sensitivity levels
   - Maintains high performance across range

4. HIGH CONFIDENCE IN MODEL
   - 93.3% AUC indicates reliable predictions
   - Model learns true patterns, not noise

Threshold Optimization from ROC:
